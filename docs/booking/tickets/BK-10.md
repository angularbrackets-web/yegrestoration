**Scope amendment, client-decided 2026-08-11:** the ROADMAP scoped this ticket
as "booking replaces the contact form; `leads` read-only." The client wants a
written channel to survive for questions, so the form is **demoted and
reframed, not deleted**: quotes and assessments have exactly one door
(`/book/`), the form becomes a general "send us a message" channel living only
on `/contact/`, and `leads` therefore **stays writable indefinitely**. The
ROADMAP P5 row and the read-only comment in `scripts/migrations/001-leads.ts`
are updated to match. Decided in conversation with the user; the funnel logic
(one quote path, one question path, one emergency path — each visitor has an
obvious door) is recorded here so a future copy edit doesn't quietly recreate
two quote doors.

Reviewed because it rewrites the site's primary conversion path, changes a
public write path (`api/contact.ts` — schema, DB semantics, send handling),
retires a live Google Ads conversion tag, and touches customer-facing email
templates. Risk areas, in the order a reviewer should weight them:

1. **Silent lead loss.** `leads.service` is `TEXT NOT NULL`
   (`scripts/migrations/001-leads.ts`) and the route swallows DB failures —
   making `service` optional without the migration means an omitted service
   violates the constraint, the catch eats it, the email still sends, and the
   visitor sees success while the row never lands. The migration, the zod
   shape, and the insert semantics must move together. Likewise the ROADMAP
   trap this ticket owns: **Resend resolves with `{ data: null, error }` and
   never throws**, so today a bounced key or an outage reaches the visitor as
   "message sent." After demotion the form is the only written channel — a
   false success costs the lead permanently.
2. **Conversion-tracking cutover.** The Ads form-conversion block is retired
   from code while the account-side action goes Secondary (user checklist
   below — never deleted). `generate_lead` survives on the message form. Any
   surviving `PUBLIC_*` read must stay a literal `import.meta.env.PUBLIC_X`
   expression (Known trap: helper-wrapped reads compile to `undefined` in the
   client bundle).
3. **Site-wide CTA repoint fan-out.** Quote CTAs live on the homepage, every
   service page, the insurance page, about, three blog posts, the mobile call
   bar, the footer, and `servicePath()`'s fallback. A missed site is a dead
   anchor or a two-door funnel; a new unslashed link is a 308. The existing
   slash scan **cannot see** several of the exact literals this ticket fixes
   (see Verification — the scan regex is extended first, red-observed).
4. **Customer-facing email copy.** The five reply templates are quote-framed,
   interpolate a possibly-absent service label unguarded (`String.replace`
   with null writes the literal text "null" into a customer email), and tell
   customers to call **(780) 244-4747 — a number the client does not
   recognize**. The advertised line is (780) 479-3285. Every admin reply since
   the templates shipped has carried a wrong number; this ticket fixes it.

## Goal

`/book/` is live and proven, but the site still routes quote intent at a
callback form: every "Get a quote" CTA anchors to the form, the form's email
arrives as "New Quote Request," and Ads optimizes toward form submits. After
this ticket: **booking is the one quote path** (every quote/assessment CTA
points at `/book/`, prefilled where intent is already declared), **the form is
the one question path** ("Have a question or want a quote? Send us a message,"
on `/contact/` only), **phone is the one emergency path** (promoted, not
buried, on `/book/` itself), and the admin leads surface — which now lives
forever — gets the fixes it has been owed: checked sends, slashed links,
timezone-correct dates, the right phone number.

## Design notes

- **One door per intent.** Quote → `/book/`; question → message form;
  emergency → phone. The reframe must not leave the form *looking* like the
  lower-commitment quote path or visitors will route around booking — that is
  why the copy says "or want a quote" (the shopper's word) while every CTA
  labelled quote/assessment goes to booking.
- **Send is the source of truth for the contact route** because the office
  works from the inbox; the DB row is the admin-surface record. The truth
  table in scope 3 is deliberate, not defensive coding — the reviewer should
  challenge the table, not the absence of one.
- **The Ads action is demoted account-side, not deleted, and not by us** —
  deleting destroys history; Secondary preserves comparability while removing
  it from Smart Bidding. Code retires the tag; the user runs the checklist.
- **Query-param prefill trusts nothing**: `?service=`/`?route=` only ever
  select an option that already exists in the form's own lists; any other
  value is ignored. No write path reads them.
- **`#contact` / `#quote` ids survive** even where CTAs repoint, so stale
  links (bookmarks, cached SERPs, the blog posts until their edit deploys)
  degrade to landing on a relevant section instead of nowhere.

### Settled during implementation

Each is the implementer's call, made because the ticket delegated the shape
rather than the spelling. Any is a reviewer's to overturn.

- **One Resend call site, and no idempotency key for the two new senders.**
  `resendSender` in `booking-notify.ts` was module-private and hard-coded
  `booking-<id>:<to>`; it is now `createResendSender(apiKey, keyPrefix)`, the
  only place in the codebase that calls `resend.emails.send`. Bookings keep
  their key. The contact form and the lead reply pass **`null`**, deliberately:
  their recipient is a fixed office address, so any fixed key would make Resend
  collapse every subsequent message into the first one. That is a worse failure
  than a duplicate.
- **`mailDisabled()` is exported from `booking-notify.ts` and shared.** Three
  paths now honour `BOOKING_NOTIFY_DISABLED`; a second definition of "mail is
  off" is how one of them stops honouring it.
- **Two different fallback strings for an absent service, on purpose.**
  `LEAD_SERVICE_UNSPECIFIED` ("Not specified") is admin-facing; templates use
  `SERVICE_FALLBACK` ("your restoration needs") because "Not specified" reads
  wrong in a sentence a customer receives. Collapsing them would put one of the
  two in the wrong register.
- **Reply templates are filled server-side.** The browser used to run its own
  copy of the `{{name}}`/`{{service}}` regexes, which is exactly how the null
  guard could live in `reply-templates.ts` and still never reach a customer.
  `fillTemplate` is now the only implementation and the page ships filled
  strings.
- **`ContactSection` gained `showForm` (default `false`), passed explicitly at
  both call sites.** `/contact/` keeps the real form; the homepage's right
  column is the booking CTA card. The GSAP stagger selector learned the card's
  nodes (`[data-contact-stagger] > *`) so the animation did not silently start
  animating nothing.
- **`MobileCallBar`'s prop is renamed `formAnchor` → `bookHref`.** The old name
  described a form that no longer exists there, and its `#quote` default would
  have pointed at a section some pages do not have.
- **`verify:cutover` is a new script, not an extension of
  `verify-booking-admin.ts`.** The sweep is site-wide and has nothing to do
  with the admin surface. It runs **its own build with sentinel labels**,
  because whether a `PUBLIC_*` value reaches the browser is a fact about
  `dist/`, not `src/` — and it therefore leaves a sentinel build behind, which
  its final line says out loud.
- **`verify:booking:form` is reported as a gate row** even though the ticket's
  gate list did not name it: it is where the prefill assertions live.
- **`name` and `phone` gained `.trim()` before `.min()`** in both the server
  schema and the form's mirror of it. A name of two spaces was valid. The
  mirror was kept no stricter than the server, per the existing rule.
- **VideoReel's panel got `role="button"` + `tabindex` + Enter/Space rather
  than a real `<button>`.** Its overlay and accent bars are `<div>`s, which a
  `<button>` may not contain; the reachability defect is fixed either way.
- **Navbar's drawer key handling moved to `<svelte:window>`.** It was on both
  the `<nav>` and the overlay — a keyboard handler on a non-interactive
  landmark, and it still missed Escape whenever focus sat outside either.
- **The three blog CTAs' link TEXT was rewritten, not just their href.** They
  said "Contact us" and "Call us any time" while pointing at the booking page;
  leaving the labels would have made every one of them lie.
- **Three broken `for=` attributes on the leads detail page were fixed**
  (`for="template"` against `id="template-select"`, and two more). They are not
  in the ticket's a11y scope — that scope is the `svelte-check` warnings — but
  the file was already open and a label pointing at a non-existent id is the
  same defect the scope names.
- **Long rationale comments were moved out of `.astro` templates.** Astro ships
  HTML comments to the browser (proved while red-observing: a comment *about*
  `noindex` in `book.astro` made the built-page assertion go red). Rationale
  lives in frontmatter; template comments are one line.

## Implementation review (2026-08-11, fresh agent)

Verdict: **approve with should-fixes** — no blockers. Findings and what was
done, all by the reviewer session, gates re-run green after:

- **Should-fix 1 — the routes' failed-arm Response mapping was the one
  truth-table row no gate observed.** Under the mute every route-level run
  reaches only `skipped`; lib-level pins the outcome *value*, not the route's
  mapping of it — so `if (outcome.ok)` in `contact.ts`, or the `failed` arm in
  `reply.ts`, could rot with every gate green, reproducing risk area 1's
  headline defect. Fixed with the reviewer's own suggested mechanism: one
  route-level run per route with the mute off and `RESEND_API_KEY` deleted
  from the environment — the missing-key arm makes `failed` reachable with
  nothing sendable. `verify-contact.ts` asserts the 500 (and that the row
  still lands); `verify-booking-admin-db.ts` asserts the slashed
  `?error=sendfailed` redirect and that the lead stays unstamped.
- **Should-fix 2 — the single-Resend-call-site invariant was pinned for
  `reply.ts` only.** `verify-cutover.ts` now sweeps all of `src/`: `new
  Resend(` / `.emails.send(` may appear only in `booking-notify.ts`. First
  red run flagged the *prose comments* in `contact.ts` and `lead-reply.ts`
  that explain the trap — the sweep strips comments before matching, for the
  same reason the label sweep matches the read expression, not the name.
- **Nits, all fixed:** the six-line HTML rationale comment shipping to the
  browser from `admin/leads/[id].astro` removed (the rationale lives in
  `reply-templates.ts`); `ContactForm.svelte`'s dead `errors.service` render
  branch and class binding removed (the schema can no longer produce one);
  `verify:cutover` now chains `npm run build` so its sentinel build never
  survives a run.
- **Scope-call, recorded not fixed:** `booking_availability_error/empty`
  re-fire on retry/refetch, so GA4 counts are *attempts*, not visitors —
  consistent with their diagnostics-only purpose; noted for BK-11's reading
  of the numbers (also in ROADMAP).
