# BK-56 — Let the owner add a line to the customer's confirmation email

**Status:** 🆕 **OPENED 2026-09-05, not planned, not started.** Named by
**decision 25**, which is the reason it exists: the user specified that the
travel-fee amount reaches the customer *"only spoken via call or the
confirmation email from the owner triggered from the admin panel"* — **and that
second channel does not exist in the software.**
**NOT a gate on BK-53 or BK-55.** The phone channel works today.

**Phase:** free-booking changeover · **Tier:** ⚠️ **Reviewed.** It is a
**customer-facing write path**, which is what makes it more than a text field.
**Depends on:** nothing. **Blocks:** nothing.

## The gap, verified 2026-09-05

- `admin_notes` (`db.ts:108`) is **office-only** — written by
  `booking-admin-entry.ts`, labelled *"Office notes"*, and it **renders in no
  customer-facing message**. `grep admin_notes src/` outside `db.ts` returns
  only commit/entry/admin files.
- There is **no free-text field on any customer email**.
- BK-51 **refuses a non-zero travel fee outright** (`review.ts:246`), so the
  amount cannot travel as money either.

So decision 25 names two channels for the $150 and the software supports one.

## Scope

- A free-text line the owner can add from the appointment detail page, rendered
  into the customer's confirmation email.
- ⚠️ **It is a send path, so it inherits the send path's rules:** idempotency
  prefix, the mute flag, and the fact that `planForAppointment` builds both the
  customer and the office message.
- ⚠️ **Decision 25 does not authorise the number on the website.** If this field
  is ever rendered anywhere but the email, that is a different ticket and a
  different decision.
- The travel-fee *amount* is already settled — **a flat $150** (decision 8;
  `PREPAY-PLAN:86`). **Do not re-ask what the number is.** ROADMAP index item 8
  struck a near-identical question as the answered-question-still-open trap.

**Decision 25**, 2026-09-05, and the verification recorded under it in
