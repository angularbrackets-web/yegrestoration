# BK-13 — Soft launch: navbar CTA points at /book/

**Status:** committed 2026-08-10. Gates green; Light tier, so no reviews owed.
(Approved 2026-08-10 by the user in-session: "yes let's do the soft launch
ticket before BK-10".)
**Phase:** P5 (pre-cutover) · **Tier:** Light · **Depends on:** BK-05 (live
`/book/`) · **Blocks:** nothing — BK-10 remains the real cutover.

Light because it is link/copy only: no write path, no PII, no schema, no config
with production side effects beyond where two anchors point.

## Goal

`/book/` went live 2026-08-10 but nothing on the site links to it — the page is
reachable only by typed URL, so no real customer will find it and the booking
conversion sees no real traffic. Give it one entry point *without* touching the
contact form, so bookings can trickle in ahead of BK-10 and the first real
customer booking happens while the contact form is still the safety net.

## Scope

1. **`Navbar.svelte` desktop CTA** — the "Free Assessment" button: `href`
   changes from `#contact` to `/book/`, dropping the `handleLinkClick` hash
   handling (page links navigate normally, per that function's existing
   contract).
2. **`Navbar.svelte` mobile drawer footer** — add a "Book a Free Assessment"
   link to `/book/` above the phone button, styled as the secondary action.
   The phone button stays primary: this is an emergency-led business and the
   drawer's hierarchy should keep saying so.

## Out of scope

- The contact form, `#contact` / `#quote` anchors, and every other CTA on the
  site (homepage hero, service cards, service-page quote forms, footer). BK-10.
- Any change to `/book/` itself.
- Removing the `#contact` branch from `handleLinkClick` — service pages and
  section links still use it.

## Assumptions log

- **The mobile drawer gets a booking link too.** The user approved "point the
  navbar's Free Assessment at /book/"; on mobile that CTA does not exist, so a
  desktop-only change would soft-launch to no one on the majority device. The
  drawer link is the same decision expressed at the other breakpoint. User can
  veto on review of the summary.
- **Label stays "Free Assessment" on desktop**, "Book a Free Assessment" in the
  drawer where there is room for the verb. No other copy changes.

## Acceptance criteria

1. The desktop navbar CTA navigates to `/book/` from any page.
2. The mobile drawer shows a booking link above the phone button; both close
   the drawer and navigate.
3. No other link's target changes; the contact form remains reachable exactly
   as before.
4. `npm run typecheck` and `npm run build` pass.

## Verification

Gates only (Light): `npm run typecheck`, `npm run build`. The changed targets
are DOM attributes in a Svelte component; this repo has no browser-test
infrastructure (BK-03/04/05 precedent: read, not asserted). No verify script
changes, so no red-first entry is owed.
