# BK-07 — Appointments list + detail in `/admin`

**Status:** plan-reviewed 2026-08-10 — 1 blocker, 2 should-fixes, 3 nits, all
accepted and folded in below. The blocker: admin login is a redirect loop in
live production under `trailingSlash: 'always'` (independently confirmed by
curl: `/admin/login` 308 → `/admin/login/` 302 → `/admin/login` …), so the
surface this ticket builds on has been unreachable since ~2026-07-04. Fix
brought into scope (item 0) per the reviewer's option (a).
**Phase:** P4 · **Tier:** Reviewed · **Depends on:** BK-05 (stamp columns) ·
**Blocks:** BK-08 (edits happen on the detail page this ticket builds), BK-09
(the file section this ticket stubs is where the proxy links land)

Reviewed because it renders PII and insurance identifiers onto a new surface.
Risk areas, in the order a reviewer should weight them:

1. **Auth coverage — now including making auth work at all.** Every new path
   must sit behind the middleware. It matches on the `/admin` prefix, so
   `/admin/appointments` and `/admin/appointments/[id]` are covered by
   construction — the reviewer's job is to confirm nothing here escapes that
   prefix (no new API route, no public-path addition, no data in a client
   island). Plan review found the flip side broken: the middleware's
   `PUBLIC_PATHS` holds only unslashed paths while production 308-normalizes
   every request to the slashed form, so login loops and **production admin
   has been unreachable since the trailing-slash change (2026-07-04)**. The
   fix (scope item 0) edits path matching in the auth middleware, which cuts
   both ways: the reviewer must confirm the normalization cannot classify a
   *protected* path as public.
2. **Timezone rendering.** `slot_start` is a UTC instant and the server runs in
   UTC. A bare `toLocaleString()` or `toLocaleDateString('en-CA', …)` without
   `timeZone` renders the *server's* zone — off by 6 or 7 hours depending on
   DST, which for a 3:30 p.m. appointment shows the wrong day's evening. The
   existing leads page does exactly this for `created_at`, where nobody
   notices; copied onto `slot_start` it sends a crew on the wrong day.
3. **PII stays server-rendered.** No appointment data may enter a Svelte
   island or client script — the page is plain `.astro`, HTML only, like the
   leads pages.
4. **Read-only against production.** This ticket runs two new SELECTs on the
   list page and two on the detail page (appointments + files), and writes
   nothing.

## Goal

Bookings are live (soft-launched 2026-08-10) and the office's only view of
them is the internal email. If that email fails — the exact failure BK-05
built `internal_notified_at` to record — the appointment exists only as a
database row, and nobody is watching the database. The stamp columns are
currently surfaced nowhere, so the failure they record is still invisible.

Give the office a read-only view: what's coming, everything about each visit,
and a loud flag when a notification never went out.

## Scope

0. **Fix admin auth under `trailingSlash: 'always'`** (plan-review blocker).
   - `src/lib/auth.ts` gains a pure, `tsx`-importable
     `isPublicAdminPath(pathname)` that answers true for the three public
     paths in either slash form and false for everything else — including
     tricky near-misses (`/admin/login-x`, `/admin/login//`,
     `/api/admin/login/extra`). The middleware uses it instead of the raw
     `Set` lookup.
   - The middleware's unauthenticated redirect targets `/admin/login/`
     (slashed) so it no longer buys an extra 308.
   - `login.astro`'s form action, `AdminLayout.astro`'s logout action, and
     `login.ts`'s success/failure redirect `Location`s all move to slashed
     form (`/api/admin/login/`, `/api/admin/logout/`, `/admin/`,
     `/admin/login/?error=1`), per the Known trap that unslashed forms 308.
   - Post-deploy check: unauthenticated `GET /admin/login/` answers 200 (it
     answers 302-loop today), and a real login lands on `/admin/`.
1. **`src/lib/booking-admin.ts`** — pure helpers, no env, no DB, importable
   under `tsx`:
   - `partitionAppointments(appointments, now)` →
     `{ upcoming, past }` — upcoming = `slot_start >= now` and status
     `booked`, ascending (soonest first); past = everything else,
     descending (most recent first). Cancelled and no-show rows are *past*
     regardless of date: they need no crew, but they stay visible because a
     cancelled slot that rebooks is tomorrow's confusion.
   - `notificationFlags(appointment)` → the "office was never told" /
     "customer never confirmed" conditions in one place: internal flag when
     `internal_notified_at` is null; customer flag when
     `confirmation_sent_at` is null **and** `email` is non-null (a customer
     who gave no email was never owed one — not a failure). Both flags only
     for `source = 'web'` rows — admin-entered appointments (BK-08) never
     had notifications to fail.
2. **`src/pages/admin/appointments/index.astro`** — `prerender = false`.
   Two queries: `SELECT * FROM appointments`, partitioned by the helper, and
   a grouped file count (`SELECT appointment_id, COUNT(*)::int FROM
   appointment_files WHERE appointment_id IS NOT NULL GROUP BY
   appointment_id`) joined in application code. Claimed rows count
   regardless of `upload_state`, matching the commit path's claim rule (the
   Known trap: `onUploadCompleted` never fires on localhost). Two sections:
   - **Upcoming** — the operational view: slot (via `formatSlot`, labelled
     Edmonton time), name, phone, service label, city, payment route badge,
     file count, and the notification warning flag when either flag is up.
   - **Past** — collapsed visual weight: slot, name, service, status badge
     (completed / cancelled / no_show / booked-but-elapsed).
   Row click → detail. Status badge colors follow the leads page's pattern.
3. **`src/pages/admin/appointments/[id].astro`** — `prerender = false`,
   parameterized SELECT by id (the id is cast/validated before the query;
   non-numeric or missing → 404). Everything on the row, grouped:
   - **Visit** — slot via `formatSlot` + Edmonton label, duration, status,
     pipeline stage, source.
   - **Customer** — name, phone (as `tel:` link), email (as `mailto:` when
     present), address / city / postal code, description.
   - **Insurance** — insurer, policy, claim; section absent entirely on the
     private route. This is the sanctioned admin surface for these fields
     (the `002-booking` column comment: email and admin panel only).
   - **Notifications** — the two BK-05 stamps rendered as sent-at times
     (Edmonton) or as explicit warnings from `notificationFlags`.
     `sms_consent_at` and `reminder_sent_at` render **neutrally**, never as
     warnings: a null consent means "no consent" (the locked rule — the
     timestamp *is* the consent, absence is a valid state), and a null
     reminder is expected on every row until BK-06 ships and the slot
     approaches. "No consent" / "not sent" in plain style.
   - **Files** — count and per-file name/size/state from `appointment_files`
     (`WHERE appointment_id = …`), no links: viewing is BK-09, and the
     section says so. Blob pathnames/URLs are not rendered even as text.
   - **Notes** — `admin_notes` verbatim (editing is BK-08).
4. **`src/layouts/AdminLayout.astro`** — a two-link nav (Leads ·
   Appointments) so both surfaces are reachable; current-page state. The
   30-second `refresh` meta the leads page uses is applied to the
   appointments list too.
5. **`src/pages/admin/index.astro`** — unchanged except whatever the shared
   nav needs; the leads list stays the `/admin` landing page until BK-10
   decides otherwise.
6. **`scripts/verify-booking-admin.ts`** + `npm run verify:booking:admin` —
   the pure helpers under `tsx`, red-first per rule.

## Out of scope

- **Any write**: status/stage edits, cancellation, blackout dates, notes
  editing, manual entry — all BK-08.
- **Viewing file contents** — BK-09 (private Blob store; direct URLs 403).
- **Resending a failed confirmation** — BK-08 at the earliest, needs a write
  and a send.
- **Pagination and search.** One crew, ≤5 slots/day, 14-day booking window:
  the table stays small for months. Recorded here so its absence is a
  decision, not an oversight.
- **The leads page's own unzoned `created_at` rendering** — pre-existing,
  cosmetic there; reviewer agreed it's worth recording, now in ROADMAP Known
  traps with owner BK-10.

## Design notes

- **Every new internal link is slashed** (`/admin/appointments/`,
  `/admin/appointments/${id}/`, nav links) — the site convention; the
  existing admin's unslashed links each eat a 308 and are the pattern not to
  copy.
- **Astro pages, zero client JS**, matching the existing admin exactly. The
  data never leaves the server-rendered HTML, which is what keeps risk area 3
  a non-issue by construction.
- **`formatSlot` is the only slot renderer.** It already exists, is
  Edmonton-aware, and is what the emails use — the admin page showing the
  same string the customer received is a feature, not a shortcut. Dates that
  are *not* slots (created_at, stamps) render through one small local helper
  that passes `timeZone: TIMEZONE` explicitly, so no bare `toLocale*` call
  appears anywhere in the new pages.
- **The warning flags are computed, not styled inline** — `notificationFlags`
  exists so "what counts as a failed notification" is a pure function a
  script can pin down, including the no-email-given and admin-source cases
  where a missing stamp is *not* a failure. The subtlety is exactly the kind
  of condition that rots when written as template ternaries.
- **`SELECT *` on the list page, matching the leads page.** The table is
  small (see pagination note) and the alternative — a column list that must
  chase the schema — is the kind of duplication BK-05's stamp columns would
  already have broken once.
- **Detail query is by validated integer id.** The Neon driver
  parameterizes, so this is defense in depth plus a clean 404 for
  `/admin/appointments/abc`.

## Acceptance criteria

1. Admin auth works end to end on production paths: unauthenticated
   `GET /admin/login/` answers 200 (no loop); a correct password lands on
   `/admin/`; unauthenticated `GET /admin/appointments/` redirects to
   `/admin/login/`; `isPublicAdminPath` answers true for the three public
   paths in both slash forms and false for protected paths and near-misses.
2. The list shows upcoming booked appointments soonest-first with slot
   rendered in Edmonton time and labelled as such; a 3:30 p.m. Edmonton
   booking renders as 3:30 p.m., never as the UTC wall-clock (9:30/10:30
   p.m.) or the wrong day.
3. `partitionAppointments`: upcoming excludes cancelled/no-show/completed
   and past slots; ordering is ascending upcoming, descending past; the
   boundary instant (`slot_start === now`) is upcoming.
4. `notificationFlags`: internal flag iff `internal_notified_at` is null and
   source is web; customer flag iff `confirmation_sent_at` is null, email
   non-null, and source is web; admin-source rows never flag.
5. The detail page shows insurance identifiers on the insurance route and no
   insurance section on the private route.
6. The detail page shows both notification stamps (time or warning), SMS
   consent, and the file list with no Blob URL or pathname in the HTML.
7. A non-existent or non-numeric id answers 404, not 500.
8. `npm run typecheck` and `npm run build` pass.
