# BK-28 — Homepage availability preview: next open slots, deep-linked into /book/

**Status:** draft 2026-08-13 — designed in a planning session (user approved the
plan); awaiting plan review by a fresh agent, then approval. Implementation is
assigned to a new session (user decision 2026-08-13).
**Phase:** P8 · **Tier:** Reviewed, narrow — no server rule changes and the
availability endpoint is untouched, which reads Light, but `applyPrefill` gains
a **new untrusted query-string input (`?slot=`) that feeds `slot_start` on the
public write path**. CLAUDE.md's "anything touching public write paths" is the
deciding clause. Risk areas for the reviewer: (1) can a crafted `?slot=` ever
submit something the availability reconcile wouldn't catch? (2) homepage
LCP/CLS. · **Depends on:** nothing functional; land **after BK-27** only
because both touch `ContactSection.astro`'s CTA card and `booking-form.ts`
(clean diffs). · **Blocks:** nothing.

## Why

User observation, client-prompted (2026-08-13): booking slots are visible only
on `/book/`; the homepage booking section is a static CTA card. Decision
(user, same day): show the next few available slots on the homepage — an
availability preview reusing the existing `/api/booking/availability/`
endpoint — each deep-linking into `/book/` with that slot preselected. Proves
real availability without duplicating the funnel.

## Design decisions

- **Pure model module + thin island.** Slot picking, href building, and
  failure handling live in a new pure module (`booking-form.ts` pattern:
  values in, values out, no DOM/network/clock) so `tsx` verify scripts can
  drive them; the island only fetches and renders.
- **Decorative strip never shows an error.** On fetch failure or zero slots,
  the preview collapses to the existing CTA (same box height) — contrast with
  the form, where the failure message is load-bearing.
- **`?slot=` is validated twice**: shape at prefill time
  (parses + `isSlotOnGrid`), truth at reconcile time (must exist in fetched
  availability, else cleared). The reconcile — today an inline check in
  `BookingForm.svelte` — is extracted to a pure helper so the forged-slot
  guarantee becomes assertable. `?slot=` is the documented exception to
  `applyPrefill`'s "only values the form already offers" rule; the reconcile
  is the actual guarantee.
- **No auto-advance** when a prefilled slot survives reconcile: it preselects
  on step 1 and the visitor confirms. (A stale deep link that reconcile clears
  would otherwise look broken. Recommendation, not a client decision — log if
  the user overrides.)

## Changes

1. **`src/lib/booking-preview.ts`** (new, pure):
   - `pickPreviewSlots(dates: AvailableDate[], n: number): AvailableSlot[]` —
     `dates.flatMap(d => d.slots).slice(0, n)`, n ≈ 3. Slots arrive
     server-ordered; do not re-sort. Render `slot.label` as-is (the "client
     never re-derives the zone" rule).
   - `previewSlotHref(slot)` —
     `` `${BOOKING_PATH}?slot=${encodeURIComponent(slot.start)}` `` from the
     `booking-config.ts` constant, never a literal (trailing-slash 308 trap).
   - Failure/empty → render-nothing display model, reusing
     `readAvailabilityResponse` from `booking-form.ts`.
2. **`src/components/AvailabilityPreview.svelte`** (new, small island): fetch
   `BOOKING_AVAILABILITY_ENDPOINT` in `onMount`; render ≤3 anchor chips
   (`<a href={previewSlotHref(slot)}>{slot.label}</a>`) + a "more times →"
   link to plain `/book/`. Fixed-height skeleton; failure/empty fills the same
   box.
3. **`src/sections/ContactSection.astro`** — mount
   `<AvailabilityPreview client:visible />` in the CTA-card branch
   (`showForm={false}`) **only** — `/contact/` renders the form branch and
   must not gain it. The GSAP stagger animates `[data-contact-stagger] > *`:
   keep the island's *wrapper* as the stagger child (targets exist at trigger
   time; content pops in later).
4. **`src/lib/booking-form.ts`** —
   - `applyPrefill` reads `params.get('slot')`; accept only if
     `new Date(raw)` parses **and** `isSlotOnGrid(parsed)` (from
     `booking-time.ts`); store **normalized** via `toISOString()` — chip
     selection and the step-1 render compare by exact string equality against
     `AvailableSlot.start`, and `+00:00` vs `Z` spellings must not defeat
     that. Update the doc comment (documented exception, see above).
   - Extract the inline reconcile (`BookingForm.svelte` ~line 202) into pure
     exported `reconcileSlotWithAvailability(slotStart, dates): string | null`
     — existing behaviour, new seam; the component keeps the same semantics
     for the "slot went away while typing" case it already handles.
5. **`src/components/BookingForm.svelte`** — swap the inline check for the
   helper (one-line change). No other behaviour change.
6. **Optional:** `booking_preview_click` in `BookingFunnelEvent`
   (`booking-handoff.ts`) + `reportBookingFunnelEvent` on chip click. Funnel
   events count attempts, not visitors (standing Known-trap reading hazard).

## Homepage LCP/CLS guardrails

The site fought for LCP 2.3s; `ContactSection` is the last section on the
prerendered homepage.

- **`client:visible`, never `client:load`** — zero hydration until the
  visitor nears the section. (`book.astro`'s `client:load` rationale does not
  apply: this island is decoration, deep below the fold.)
- **Fetch only post-hydration in `onMount`** — no SSR/build-time fetch (the
  page is prerendered; a build-time read would be stale and add a build→DB
  dependency), no network during the LCP phase.
- Marginal JS is one lazy chunk — the homepage already ships the Svelte
  runtime (`Navbar client:load`).
- **Reserve the chip row's final height** in the static card markup (one
  fixed-height flex row) — zero CLS. CLS, not LCP, is the metric this island
  can actually damage; an unsized late row inside a GSAP-animated card is
  exactly how. Empty/failure states fill the same box.
- Nothing else: no new fonts, images, or `<head>` additions.

## Sequencing

- **No coupling to BK-23.** The preview consumes the availability endpoint
  as-is; when BK-23 widens filters (declined) and moves notice 4h → 24h, the
  preview inherits both for free (earliest chip moves a day out — cosmetic).
- **BK-18** (picker redesign, deferred behind P7) replaces the step-1 UI but
  not `applyPrefill`/`FormValues.slotStart` — BK-18 must preserve the
  `?slot=` preselect and the reconcile helper. Noted in its P6 row's

- **Availability endpoint caching**: every homepage scroll-to-bottom adds a
  GET. Volume is trivial; do **not** add cache headers in this ticket (the
  endpoint is a Reviewed surface this ticket otherwise doesn't touch). Note,
  not work.

## Verification (gates + red-first)

In `scripts/verify-booking-form.ts` (owns `applyPrefill`; no new script):

- `applyPrefill` + `?slot=`: valid on-grid ISO → `slotStart` set to the
  normalized `toISOString()` form (feed a `+00:00` spelling, assert the `Z`
  form comes out); off-grid instant / garbage / empty / injected-HTML →
  ignored; `slot` combined with `service`/`route` still applies all.
- `reconcileSlotWithAvailability`: present → kept; absent → null; null → null.
- `pickPreviewSlots`: skips empty days, preserves cross-day order, caps at n,
  empty availability → `[]`.
- `previewSlotHref`: starts with `BOOKING_PATH` (slashed); query value
  survives a `URLSearchParams` round-trip.
- Failure path: `readAvailabilityResponse(500, {})` piped into the preview
  model → renders-nothing state (assert the pure model, not the DOM).
