## Why this ticket exists separately

BK-53 was one ticket doing six jobs and did not close in four review rounds.
**Decision 24 split it by SURFACE GROUP, not copy-vs-gate** — because within a
claim the copy edit and its pin must be **one commit** (`CONVERSION` §7
constraint 5: *"pin first and the build goes red; copy first and there is an
unpinned window"*). So each half carries its own copy **and** its own pins.

**This half is where the blast radius is.** It is the reason the adversarial
pass exists, and separating it means that pass lands on the money path instead
of being spread across two tickets.

## Scope — four items, all previously found and verified

### 1 · 🔴 The request email prices the assessment, and the fixtures REQUIRE it

`booking-email.ts:1159-1168`:

```ts
const weekend = quote.afterHours ? ' — weekend rate, 1.5x' : '';
return `${name} — ${formatCents(quote.baseCents)} + GST (${formatCents(quote.totalCents)} total)${weekend}`;
```

`:411` forces `settled = null` on a request, so `tierLine` (`:456-462`) takes
the `assessmentSummary` branch for **every request email — the first message
every web customer receives.** It renders *"You chose: Assessment + written
report — $699.00 + GST ($733.95 total) — weekend rate, 1.5x"*.

⚠️ **It is computed from `assessmentQuote`, not from any constant**, so **no copy
deletion touches it** and no claim-shape pin sees it — email bodies never reach
`dist/`. **It defeats decision 17 and decision 21 at once.**

🔴 **`verify-booking-email.ts:2013-2045` asserts `$399.00`, `$418.95`, `$577.50`,
`$606.38` and `weekend rate` — and `mouldBody` is the CUSTOMER's message.**
Per CLAUDE.md's BK-44 trap: establish each arm relied on the old behaviour,
**make the fixture honest, never loosen the rule.**

**Fix:** under decisions 17/20/21 the request email names the tier and **no
figure** — `return name;`.

### 2 · `FEE_TERMS_ITEMS` — figures stripped, array KEPT

🔴 **Do not delete it.** `booking-email.ts` renders `ASSESSMENT_TIER_NAMES` only;
`ASSESSMENT_TIER_DESCRIPTIONS` renders on one surface (`BookingForm.svelte`).
**So this array is the ONLY path by which the 3–5 day lab turnaround — a client
requirement of 2026-08-18 — reaches any email.** Deleting it also drops BK-27
Q4's *"each tier includes the ones below"*, which BK-36 dropped once and plan
review restored. Copy is drafted and **approved** (decision 26) in
`BK-53.md` revision 3 §1.

### 3 · 🔴 The resend defect — decision (b), and it is this ticket's adversarial target

`resend.ts:94` refuses anything but `status === 'confirmed'`, then `:106` builds
the **confirmed** message from **today's** constants. So after the flip, the
office clicks Resend on `#36` — `confirmed`, `cs_live_`, **$628.43** — and that
customer receives *"the visit is free… a travel fee may apply… quoted
separately"* beside their real charge, **with no refund policy at all.**
**Strictly worse than the pre-ticket defect**, which at least shipped a refund
policy of the wrong era.

**DECIDED (revision 4, R4-3) — option (b):** suppress the terms block for any
row whose `terms_acked_at` predates the deploy, and render
*"The terms you accepted are in your original confirmation email."*
**Option (a), the terms snapshot at insert, is BK-54** — an insert-path change,
and under decision 16 the one structure that survives arbitrary pricing flips.
**BK-54 is not a gate on this ticket.**

⚠️ **R1-D2 rides here:** `settledAmountsOf` returns **null** for the thirteen
migration-008 pre-prepay rows, so any gate must be **three-state**
(`null` / `0` / `>0`). Written `settled.totalCents > 0` it does not typecheck;
written `settled?.totalCents > 0` it routes the null rows into the FREE branch.

### 4 · `CANCEL_LINE`, `APPROVED_*`, and the arms around them

- **`FEE_TERMS_REFUND[4]` IS `CANCEL_LINE`** (`booking-copy.ts:509`). Deleting
  the array silently removes **one of its two renders in every customer email**.
  **Positively pin the survivor** at `booking-email.ts:574`/`:627` so it stops
  being an accidental one. *(The web-surface half of this is BK-53's.)*
- **`APPROVED_*` (`:738-771`) carries the refund and deadline terms** — decision
  19, whose wording is still open. It is the only message a hand-charged
  customer receives, and today it carries no terms at all.
- **KEEP, explicitly** (still true, do not sweep): `DECLINED_LEAD` `:704`,
  `EXPIRED_REQUEST_LEAD` `:784`, `PAYMENT_EXPIRED_LEAD` `:828`.
  ⚠ `PAYMENT_EXPIRED_LEAD` says *"was not paid for by the deadline, so we have
  released it"* — **about a free assessment.** Give it a verdict.
- **`FEE_TERMS_PAYMENT` is index-addressed** in `booking-email.ts:1150`
  (`slice(0,2)`) and `verify-booking-email.ts:538-540`, `:556-560`. **Convert to
  named constants** — shrinking the array silently changes what `slice` returns.

## The gate

**Every `verify-booking-email.ts` arm is this ticket's.** Classify before
touching, per BK-44: **Class 1** rewrite to assert the replacement, **Class 2**
re-point at new constants, **Class 3** delete only where the subject is genuinely
gone. Named so far: `:246-254`, `:291-296`, `:304`/`:311`/`:321`, `:339-349`,
`:374`, `:424`, `:525-547`, `:638`, `:742-745`, **`:2013-2045`**, `:2037-2043`.

**Rules, all bought by earlier tickets:**
- ⚠️ **DELETE constants; never EMPTY them.** An emptied array makes
  `for (const line of carries)` run **zero iterations and stay green having
  asserted nothing.**
- ⚠️ **Pre-register the expected assertion count IN THIS TICKET before touching
  code**, and score on **(exit code, summary line)** — a count read off the
  post-change run cannot contradict that run.
- ⚠️ **Red-first: assert the break LANDED** before scoring it, and restore from a
  **file backup** — `git checkout --` reverts to HEAD and eats uncommitted work.
- ⚠️ Clear stranded probe rows first: `npm run verify:booking:admin:db -- --reset`.
