### C-1 · 🔴 Decision 29's THREE STATES stand; its DISCRIMINATOR was wrong and is corrected here

**Decision 29 adopted the plan review's B5 suggestion — key the paid-era branch
on `total_amount_cents > 0` rather than a deploy clock. Re-derived against the
enumerated cases, that misclassifies a population, so it is amended.**

*(This is CLAUDE.md's rule-rewrite trap caught rather than repeated: the predicate
changed, so every case under the old predicate was re-derived.)*

| Population | `total_amount_cents > 0`? | Terms they actually accepted |
| --- | --- | --- |
| Pre-flip web booking, charged | **yes** | paid-era ✅ classified right |
| **Post-flip hand-charged booking** | **yes** | **CURRENT terms** 🔴 **misclassified** |
| Post-flip free booking | no (`0`) | current ✅ |
| The 13 pre-prepay rows | **NULL** | none — predate migration 005 |
| Admin/phone booking | NULL until approved | **none — exempt by design** |

**The question is *which terms did this customer agree to*, and that is temporal,
not monetary.** Money is a proxy that was exact only while every booking was
charged — i.e. only before the flip this ticket ships.

**→ The discriminator is `terms_acked_at` against a named constant:**

```ts
// booking-config.ts — set to the push date when BK-51/53/55 go out, then pinned.
export const TERMS_ERA_CUTOFF = new Date('2026-__-__T00:00:00Z');
```

| `terms_acked_at` | Branch | What renders |
| --- | --- | --- |
| **NULL** | accepted nothing — admin/phone entry (exempt by design) or pre-migration-005 | *"This booking was taken over the phone. Our current terms are on the website."* |
| **< `TERMS_ERA_CUTOFF`** | paid-era | *"The terms you accepted are in your original confirmation email."* |
| **≥ `TERMS_ERA_CUTOFF`** | current | the terms block, rendered normally |

🔴 **NULL MUST BE ITS OWN BRANCH, TESTED FIRST.** In JS `null < someDate`
coerces to `0 < someDate` → **true**, so a two-branch gate routes **every phone
booking** into the paid-era arm and tells a customer who accepted nothing that
their acceptance is on file. **`verify-booking-commit.ts:806` pins that admin rows
