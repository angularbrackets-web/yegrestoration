# BK-04 — Confirmation page, success state, conversion event

**Status:** committed 2026-08-09 — Light tier, no reviews by design. Gates
green, red-first 6/6. **Done.**
**Phase:** P2 · **Tier:** Light · **Depends on:** BK-03 · **Blocks:** nothing

Light: one new static page, one island, copy, and analytics config. No new
endpoint, no database write, no PII leaving the browser it was typed into,
nothing irreversible. Gates only — no plan review, no implementation review.

## Goal

BK-03 ends a successful booking in an in-card success block on `/book/`. That
block is server-truthful but it is not a destination: it has no URL for the
client to point a GA4 key event or a Google Ads conversion at, a refresh throws
it away and shows an empty form, and no conversion event fires at all today —
the booking funnel is invisible to Ads while the contact form it replaces is
fully tracked.

Land the flow on a real URL, carry the settled client copy there, and report the
conversion exactly once per booking.

## Decisions taken by the user (2026-08-09)

Both were asked rather than assumed, because they change the deliverable and
touch the client's Ads account.

1. **A real page at `/book/confirmed/`**, not an enriched inline block. The
   island hands the confirmation over in `sessionStorage` and navigates; the
   reference number never enters the URL, the history, or the `Referer` header,
   and no URL can be hand-crafted to render a confirmation for a booking that
   is not the visitor's.
2. **Its own Google Ads conversion action**, `PUBLIC_AW_BOOKING_LABEL` — a
   booked assessment is worth more than a contact-form lead and must be biddable
   separately. **And** a GA4 `booking_confirmed` event alongside it; the two are
   not exclusive.

Four additions the user attached to those decisions, restated here as scope:

- The confirmed page is a revisitable URL, so the conversion must not re-fire on
  refresh: report with `transaction_id` = the appointment id **and** gate on a
  once-per-booking marker.
- Navigate to `/book/confirmed/` **with the trailing slash** (Known traps), and
  handle a direct hit carrying no payload by redirecting to `/book/` rather than
  rendering an empty shell.
- The page carries the settled client copy: the "call or text to cancel or
  reschedule" line and the what-to-have-ready list.
- `noindex` the page and keep it out of the sitemap — the same treatment BK-03
  gave `/book/`.

## Scope

1. **`src/lib/booking-confirmation.ts`** — the pure half, so the decisions can be
   verified without a browser the way `booking-form.ts` is. Storage keys,
   `serializeConfirmation` / `readConfirmation` (shape validation),
   `shouldReportConversion(marker, id)`, `conversionCalls({ awId, bookingLabel,
   id })` returning the gtag calls to make rather than making them, and
   `planConversionReport(…)` — the whole fire-then-remember decision, including
   the marker value to store, so the sequence is assertable without a DOM.
2. **`src/lib/booking-handoff.ts`** — the browser adapter, and the only file that
   touches `sessionStorage`, `window.gtag`, or `import.meta.env`. Keeping it
   separate is what lets the module above be imported by a `tsx` script at all:
   `import.meta.env` is undefined under plain Node (ROADMAP Known traps).
3. **`booking-config.ts`** — `BOOKING_PATH` and `BOOKING_CONFIRMED_PATH`, both
   with the trailing slash, beside the endpoint constants that exist for exactly
   this reason.
4. **`BookingForm.svelte`** — on 201, store the confirmation and
   `location.replace()` to the confirmed page.
5. **`BookingConfirmation.svelte`** — reads the payload, renders the
   confirmation, reports the conversion once, redirects to `/book/` when there
   is no payload.
6. **`src/pages/book/confirmed.astro`** — `noindex`, same shell as `/book/`.
7. **`astro.config.mjs`** — sitemap filter excludes the new route too.
8. **`src/env.d.ts`**, **`.env.example`**, **`docs/google-ads-tracking-setup.md`**
   — the new label, documented where the client will look for it. The runbook
   gains a Step 6 (create the action) and its later steps renumber.
9. **`scripts/verify-booking-confirmation.ts`** + `npm run
   verify:booking:confirmation`.

## Out of scope

  launch, no self-service cancel link, so this ticket ships no cancel token and

- **The confirmation email.** BK-05 owns it. The page therefore promises no

- **Creating the Ads conversion action and setting the env var.** A client

- **The 13 pre-existing `svelte-check` a11y warnings.** Untouched, owner BK-10.

## Design notes

- **Why `sessionStorage` and not a query string.** `/book/confirmed/?ref=481`
  renders whatever the URL says, so a hand-crafted link produces a confirmation
  for a booking that does not exist or is not the visitor's, and the reference
  number rides along in history and in the `Referer` sent to every third-party
  asset. `sessionStorage` is tab-scoped, same-origin, dies with the tab, and
  cannot be linked to. The cost — the page cannot be rendered server-side — is
  paid anyway, because `output: 'static'`.
- **`location.replace`, not `assign`.** `assign` leaves `/book/` in history, so
  Back lands a just-booked visitor on a fresh empty form — an invitation to book
  the same assessment twice. `replace` sends Back to wherever they came from.
- **The inline success block stays as a fallback.** `sessionStorage.setItem` can
  throw (storage disabled, quota). The booking has already committed at that
  point, so the one thing that must not happen is losing the confirmation. If
  the handoff fails the island keeps the BK-03 in-card success state and reports
  the conversion from there instead, using the same helpers.
- **Firing at hydration is safe.** `Analytics.astro` assigns `window.gtag` in a
  **non-async** `is:inline` script that pushes into `dataLayer`; only the
  `gtag/js` loader is `async`. So `window.gtag` exists synchronously before any
  island hydrates, and calls made at hydration queue rather than race.
- **Two independent guards against a double count, deliberately.** The marker
  stops the second `gtag` call from ever being made, which is what keeps GA4's
  `booking_confirmed` count honest. `transaction_id` is what lets *Google* drop
  a duplicate the marker cannot see — a second tab, a cleared session, a
  bookmarked confirmed URL opened tomorrow. Neither subsumes the other.
- **A navigation is not instant, so the form needs a `leaving` state.** The
  commit's `finally` clears `submitting` and releases the submit guard, and it
  runs *before* the browser has finished unloading. Without a separate flag the
  button re-enables for that window and a second click books a second
  appointment — the exact double-commit BK-02 declined idempotency over. Both
  the button's `disabled` and the first line of `handleSubmit` read it.
- **`readConfirmation` validates shape, not plausibility.** It requires `id` to
  be a finite number and `slotLabel` a string, and nothing more. Requiring
  `id > 0` or a non-empty label would be stricter than `mapCommitResponse`,
  which defaults them to `0` and `''` when a 201 arrives malformed — and
  bouncing a visitor whose booking *did* commit back to an empty form is a worse
  outcome than rendering a confirmation with no reference number on it.

## Acceptance criteria

1. A successful booking lands on `/book/confirmed/` — with the trailing slash.
2. `/book/confirmed/` visited directly, with no stored payload, redirects to
   `/book/` and renders no confirmation.
3. The page shows the appointment time, the address, that the visit takes about
   30 minutes, the have-ready list, and the call-or-text line.
4. The Ads conversion carries `transaction_id` = the appointment id.
5. Reloading `/book/confirmed/` does not report the conversion a second time.
6. A second, different booking in the same tab does report again.
7. No Ads conversion is emitted when `PUBLIC_AW_ID` or
   `PUBLIC_AW_BOOKING_LABEL` is unset; `booking_confirmed` still is.
8. A malformed or absent stored payload never renders a confirmation.
9. `/book/confirmed/` carries `noindex, nofollow` and is absent from
   `sitemap-0.xml`; `/book/` still is too.
10. `npm run typecheck` and `npm run build` pass.

## Assumptions log

- **The page promises no confirmation message.** BK-05 has not shipped, so
  copy saying "check your email" would be false on the day this lands. The
  page states what is true now: the appointment, and how to change it.
- **The have-ready list is the one settled for the confirmation email**
  (ROADMAP, open question 2). Restating it on screen is not a new copy
  decision; the client edits both later.
- **`booking_confirmed` is a custom GA4 event, not `generate_lead`.**
  `ContactForm.svelte` already fires `generate_lead`; reusing it would merge
  bookings into the contact-form count in GA4 the same way reusing the Ads label
  would merge them in Ads, which is the thing decision 2 rejected.
- **The stored confirmation has no TTL.** It is tab-scoped and overwritten by
  the next booking, so the only way to see a stale one is to navigate back to
  the confirmed URL in the same tab — where showing the visitor their own most
  recent booking is the right answer.
- **`address` is stored as one display string** (`address, city`), not as
  fields. The page renders it; nothing parses it.

## Red-observed

Six failure modes, each broken at the production target (never the script),
observed red, target restored. 6/6 went red and the script returned to exit 0.

| Broken target | Observed |
| --- | --- |
| `BOOKING_CONFIRMED_PATH` loses its trailing slash | `the confirmed path ends with a trailing slash` — the Known trap this constant exists for |
| `readConfirmation` stops requiring an `id` | 3 red: a payload with no id / a non-number id / `NaN` all read as confirmations |
| `shouldReportConversion` ignores the marker | 2 red: `reloading the confirmed page does not report the same booking twice` |
| `transaction_id` dropped from the Ads conversion | `the Ads conversion carries transaction_id…` |
| the `awId && bookingLabel` guard removed | 4 red, including `no Ads conversion is emitted without a booking label` — the `undefined/undefined` send_to |
| `planConversionReport` returns a constant marker instead of the id | 4 red: the reload fires again, and a second booking cannot report |

**A note on what is *not* covered.** ACs 1, 2 and 3 are DOM behaviour —
`location.replace` on commit, `location.replace` back to `/book/` on a
payload-less visit, and the rendered copy. This repo has no browser-test
infrastructure (BK-03 shipped the whole island without one), and adding
Playwright for a Light ticket is not this ticket's call. Two things narrow the
gap rather than close it: the reporting *sequence* — fire, then remember, which
is the part a browser would be needed to watch — was moved into
`planConversionReport` and is asserted directly; and the pre-hydration HTML was
read off `dist/`. What remains unverified is three `window.location` calls and
the copy, and a reviewer should read them rather than trust this table.

The **`.env.local` mutation** above is the one step here that touched a file
outside the diff. It is restored and verified restored, but it is called out
because a session that died mid-run would have left test conversion IDs in a
real env file.
